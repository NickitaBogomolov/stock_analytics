# 1. Требования (SRS / User Stories)

**Проект:** Market Analytics — веб-приложение для анализа рынка ценных бумаг
**Предметная область:** экономика / финансы (технический анализ и метрики риска акций)
**Версия документа:** 1.0

## 1.1 Назначение и границы системы

Приложение позволяет частному инвестору или аналитику загрузить исторические дневные котировки
ценной бумаги (CSV), рассчитать ключевые метрики доходности и риска, технические индикаторы,
сигналы и сравнить несколько инструментов между собой.

Входит в систему:
- расчётное ядро на C++ (библиотека + консольная утилита `market_cli`);
- порт ядра на Kotlin и веб-сервис на Ktor (REST API + веб-интерфейс);
- демонстрационный набор синтетических котировок.

- загрузка и регулярное обновление реальных котировок Московской биржи (ISS API);
- хранение инструментов, котировок, истории анализов и сравнений в PostgreSQL;
- развёртывание через Docker Compose.

Не входит: внутридневные (тиковые/минутные) котировки и потоковые данные в реальном времени, учётные записи пользователей, торговые операции,
инвестиционные рекомендации (сигналы носят учебный характер).

## 1.2 Глоссарий

| Термин | Определение |
|---|---|
| Свеча (OHLCV) | Дата, цена открытия (Open), максимум (High), минимум (Low), закрытие (Close), объём (Volume) за торговую сессию |
| SMA(n) | Простая скользящая средняя цен закрытия за n сессий |
| RSI(n) | Индекс относительной силы (0–100), сглаживание Уайлдера; ≥ 70 — перекупленность, ≤ 30 — перепроданность |
| Доходность | `close_t / close_{t-1} − 1` |
| Волатильность (годовая) | Выборочное СКО дневных доходностей × √252 |
| Максимальная просадка | Наибольшее падение от исторического пика до последующего минимума, % |
| Коэффициент Шарпа | `(средняя дневная доходность × 252 − безрисковая ставка) / годовая волатильность` |
| Сигнал пересечения | BUY — быстрая SMA пересекла медленную снизу вверх; SELL — сверху вниз |
| Тренд | UPTREND, если SMA_fast > SMA_slow и цена > SMA_slow; DOWNTREND — зеркально; иначе SIDEWAYS |

## 1.3 Пользовательские истории и критерии приёмки

### US-1. Каталог инструментов
*Как* инвестор, *я хочу* видеть список доступных инструментов с последней ценой и изменением за период,
*чтобы* быстро выбрать бумагу для анализа.

- **AC-1.1** При открытии страницы отображаются все CSV-файлы из каталога данных: тикер, диапазон дат, последняя цена, изменение в % (▲/▼).
- **AC-1.2** Файлы с ошибками формата не ломают список (пропускаются).
- **AC-1.3** `GET /api/instruments` возвращает 200 и JSON-массив.

### US-2. Анализ инструмента
*Как* аналитик, *я хочу* получить по выбранной бумаге метрики доходности и риска, графики и сигналы,
*чтобы* оценить её поведение.

- **AC-2.1** Отображаются: последняя цена, доходность за период, годовая волатильность, макс. просадка, коэффициент Шарпа, RSI с зоной, тренд.
- **AC-2.2** График цены закрытия с SMA fast/slow и маркерами BUY (▲) / SELL (▼); отдельный график RSI с уровнями 30/70.
- **AC-2.3** Таблица сигналов (дата, тип, цена), новые сверху.
- **AC-2.4** Для неизвестного тикера — 404, для недопустимого (`../x`) — 400.

### US-3. Настройка параметров
*Как* аналитик, *я хочу* менять периоды SMA, RSI и безрисковую ставку, *чтобы* подбирать стратегию.

- **AC-3.1** Периоды — целые 1..500, ставка — число −50..100; иначе 400 с понятным сообщением.
- **AC-3.2** Если fast ≥ slow или данных меньше `max(slow, rsi) + 1` — 422 и текст ошибки в интерфейсе.
- **AC-3.3** По умолчанию: SMA 10/30, RSI 14, ставка 0 %.

### US-4. Загрузка собственного CSV
*Как* инвестор, *я хочу* загрузить свой файл котировок, *чтобы* проанализировать любую бумагу.

- **AC-4.1** Формат: заголовок `Date,Open,High,Low,Close,Volume`, дата `YYYY-MM-DD`, разделитель — запятая.
- **AC-4.2** Проверяется: 6 колонок; числа только в десятичной записи; цены > 0; `low ≤ min(open, close)`, `high ≥ max(open, close)`; объём — целое ≥ 0; даты строго возрастают; есть хотя бы одна строка данных.
- **AC-4.3** При ошибке пользователь видит причину **и номер строки** (HTTP 422 `{error, line}`).
- **AC-4.4** Размер файла ≤ 5 МБ (проверяется в браузере и на сервере).

### US-5. Сравнение инструментов
*Как* инвестор, *я хочу* сравнить 2–8 бумаг, *чтобы* выбрать лучшее соотношение доходности и риска и оценить диверсификацию.

- **AC-5.1** График цен, приведённых к 100 на первую общую дату.
- **AC-5.2** Таблица метрик по каждому инструменту.
- **AC-5.3** Матрица корреляций дневных доходностей (по общим датам), диагональ = 1.
- **AC-5.4** Выбрано < 2 или > 8 инструментов — 400.

### US-6. Квант-лаборатория (C++)
*Как* инвестор, *я хочу* проверить стратегию на истории, оценить риск будущих потерь и подобрать доли бумаг в портфеле, *чтобы* принимать решения на основе расчётов, а не только графиков.

- **AC-6.1 Бэктест.** Стратегия пересечения SMA проверяется для всех пар fast 2…50 (шаг 2) и slow 10…250 (шаг 10) с учётом комиссии; лучшая пара выбирается на первой части истории (по умолчанию 70 %) и проверяется на оставшейся; результат сравнивается с «купить и держать». Решение дня t исполняется по цене дня t+1 (без заглядывания в будущее).
- **AC-6.2 Монте-Карло.** Не менее 10 000 сценариев бутстрепа исторических доходностей на горизонт 5–252 торговых дня; выводятся VaR и CVaR 95 / 99 %, вероятность убытка, веер цены (5/25/50/75/95 %) и гистограмма; результат воспроизводим при одинаковом seed.
- **AC-6.3 Портфель.** Для 2–10 бумаг по общим датам строятся годовые доходности и ковариационная матрица; перебирается не менее 20 000 портфелей (только покупка, сумма долей 100 %); выводятся портфели с максимальным Шарпом, минимальным риском и равными долями.
- **AC-6.4** Расчёты выполняет C++ модуль; каждый результат сохраняется в БД и открывается из истории; время расчёта в C++ показывается пользователю. Если модуль не собран — HTTP 503 и понятное сообщение.
- **AC-6.5** Kotlin-порт индикаторов совпадает с C++ ядром (|Δ| ≤ 1e-6) — проверяется автотестом (этап 4).

### US-7. Консольный отчёт
*Как* разработчик, *я хочу* получить отчёт из командной строки, *чтобы* использовать ядро без веб-сервера.

- **AC-7.1** `market_cli file.csv [--fast N --slow N --rsi N --rf PCT] [--summary] [--out report.json]`.
- **AC-7.2** Коды выхода: 0 — успех, 1 — ошибка данных, 2 — ошибка аргументов.

### US-8. Хранение данных и история анализов
*Как* аналитик, *я хочу*, чтобы загруженные бумаги и результаты анализов сохранялись, *чтобы* возвращаться к ним после перезапуска и сравнивать с прошлыми расчётами.

- **AC-8.1** Загруженный CSV сохраняется в PostgreSQL; повторная загрузка того же тикера заменяет котировки; инструмент виден в каталоге после перезапуска.
- **AC-8.2** Каждый анализ сохраняется (параметры, движок, метрики, ряды, сигналы) и доступен в истории; сохранённый отчёт открывается без пересчёта и совпадает с исходным.
- **AC-8.3** Удаление инструмента удаляет его котировки и историю (каскадно); демо-инструменты в интерфейсе не удаляются.
- **AC-8.4** Некорректные данные не попадают в БД ни частично, ни полностью (транзакция + `CHECK`-ограничения).

### US-9. Актуальные котировки с биржи
*Как* инвестор, *я хочу* анализировать реальные бумаги Московской биржи с актуальными ценами, *чтобы* выводы относились к настоящему рынку, а не к демонстрационным данным.

- **AC-9.1** При первом запуске загружаются дневные свечи за 3 года для индекса IMOEX и списка крупнейших акций (настраивается).
- **AC-9.2** Любую акцию режима TQBR или индекс можно добавить по тикеру; для несуществующего тикера — 404 и понятное сообщение.
- **AC-9.3** Котировки догружаются при старте, каждые 6 часов и по кнопке «Обновить с биржи»; последние 7 дней перезаписываются (незакрытая дневная свеча).
- **AC-9.4** У каждой бумаги видны источник и время последнего обновления; некорректные свечи биржи пропускаются, а не ломают загрузку.
- **AC-9.5** Если биржа недоступна, приложение продолжает работать с уже сохранёнными данными (502 только для явного запроса к бирже); при пустой базе подгружаются демо-данные с явной меткой.

| ID | Требование |
|---|---|

## 1.5 Формат входных данных

```csv
Date,Open,High,Low,Close,Volume
2024-01-02,120.36,121.79,115.32,116.71,2463919
2024-01-03,116.20,116.67,115.00,115.46,1682551
```

Допускаются пустые строки, пробелы вокруг значений, окончания строк CRLF, заголовок в любом регистре.
