# 3. C++ и Kotlin: разделение ролей и сравнение

## 3.0 Кто за что отвечает

Языки не дублируют друг друга в продукте — каждый делает то, в чём он сильнее:

| | **Kotlin (web-kotlin)** — сервис | **C++ (core-cpp)** — квант-лаборатория |
|---|---|---|
| Задачи | загрузка котировок с Мосбиржи, PostgreSQL, REST API, веб-интерфейс, интерактивный анализ: индикаторы, метрики, сравнение бумаг, история | бэктест стратегии с перебором параметров и проверкой вне выборки; Монте-Карло (VaR / CVaR, веер сценариев); оптимизация портфеля по ковариационной матрице |
| Характер нагрузки | много лёгких запросов, ввод-вывод, сеть, БД | мало запросов, но каждый — сотни тысяч–миллионы операций с числами |
| Почему этот язык | корутины, JDBC, сериализация, Ktor — быстро писать надёжный сервис | предсказуемая скорость без GC, плотные массивы `double`, `std::mt19937_64`, `nth_element` |
| Пример объёма | один анализ — ~500 точек, < 10 мс | бэктест: 570 пар × 350 дней; Монте-Карло: 100 000 сценариев × 252 дня ≈ 25 млн шагов; портфель: 300 000 вариантов × N² |

Связь: Kotlin выгружает котировки из БД во временные CSV, запускает `market_cli <команда>`, получает JSON и
сохраняет его в таблицу `lab_run` (история лаборатории). Команда `market_cli analyze` и Kotlin-порт индикаторов
`market.core` реализуют одну и ту же логику (этап 4 «портирование»): их совпадение проверяет `EngineParityTest`
(все метрики, сигналы и ряды SMA на 4 наборах данных, допуск 1e-6), а в интерфейсе анализ выполняет Kotlin.

Замеры C++ модуля (демо-данные, 500 сессий): перебор 1 722 пар SMA — 4 мс; Монте-Карло 100 000 × 252 дня — ≈ 1 с;
200 000 портфелей из 4 бумаг — 20 мс.

## 3.2 Сравнение по аспектам

| Аспект | C++17 | Kotlin (JVM) |
|---|---|---|
| Отсутствующее значение | `NaN` + `std::isnan`; легко забыть проверку | `Double?` — компилятор заставляет обработать `null` |
| Ошибки | `MarketDataError : std::runtime_error`, `std::invalid_argument` | `MarketDataException`, `require()` → `IllegalArgumentException` |
| Разбор чисел | `std::stod` принимает `0x1A`, `inf` — нужен белый список символов | `toDoubleOrNull` принимает `NaN`, `0x1p3`, `11d` — та же проблема, то же решение (регулярное выражение) |
| Работа с коллекциями | циклы по индексам, `std::accumulate` | `map`, `zipWithNext`, `sumOf`, `average` — короче и декларативнее |
| Сериализация | ручная сборка JSON (~40 строк) | `kotlinx.serialization` (аннотация) |
| Управление памятью | RAII, значения на стеке, без аллокаций в горячих циклах | GC; списки `List<Double>` — boxing |
| Скорость (500 сессий, замер) | `market_cli` целиком (запуск, чтение, расчёт, JSON) ≈ 3,5 мс; HTTP-запрос с `engine=cpp` ≈ 13 мс | HTTP-запрос с `engine=kotlin` ≈ 9 мс (после прогрева JIT) |
| Сборка и зависимости | CMake + FetchContent (GoogleTest) | Gradle Wrapper + Maven Central |
| Тестирование | GoogleTest: `EXPECT_*`, `TEST` | JUnit 5 + Kotest assertions, параметризованные тесты, `testApplication` для HTTP |
| Интеграция в веб | вызов как процесс (`market_cli`), JSON в stdout | Ktor напрямую использует ядро |
| Работа с БД | — (ядро получает CSV; из веба — временный файл, выгруженный из PostgreSQL) | JDBC + HikariCP + Flyway, `use {}` для ресурсов, транзакции через лямбду |

## 3.3 Выводы

- **C++** даёт предсказуемую производительность и контроль над памятью, но требует больше
  кода на «инфраструктуру» (JSON, разбор аргументов) и внимательности к `NaN` и неявным
  преобразованиям.
- **Kotlin** компактнее (~на 22 % меньше кода ядра), безопаснее за счёт null-safety и
  богаче стандартной библиотекой; для веб-сервиса — естественный выбор.
- Архитектура «ядро без зависимостей + JSON на выходе» позволила подключить C++ к Kotlin-серверу через
  адаптер `CppEngine` без изменения ядра. В итоге C++ отвечает за тяжёлые расчёты лаборатории, Kotlin — за
  сервис и интерактивный анализ.
- Портирование выявило общий класс дефектов (слишком «щедрый» разбор чисел) в **обеих**
  реализациях — см. отчёт о тестировании, D-02.
